# 실행 환경

`~/claude-review/`는 기존 리뷰 산출물 경로이며 Claude 설치 경로가 아닙니다. 세 CLI에서 동일한 용도로 사용하되, 쓰기 권한이 없으면 허용된 격리 경로를 확인하고 workflow의 WT·DRAFT 및 상태 파일 경로를 일관되게 지정합니다. 기존 리뷰 재개 시에는 기록된 경로를 사용합니다.

- 이 지침은 Claude Code·Codex·Gemini CLI에서 공통으로 사용합니다. 업무 단계·판단 기준·산출물은 유지하고, 파일 읽기·검색·웹 조회·셸 실행은 현재 호스트가 제공하는 해당 기능으로 수행합니다.
- **사용자 질문**은 현재 모드에서 허용된 질문 도구로 합니다. 도구가 없거나 호출이 거부되면 대화로 직접 묻고 실제 답변을 기다립니다. 선택지·질문 수 제한은 실제 스키마를 따르며, 후보가 많으면 질문을 나누거나 직접 입력으로 받습니다. 후보와 취소 경로를 삭제하지 않으며 무응답·기본 선택값·시간 경과를 동의로 간주하지 않습니다.
- **도구 준비**는 필요한 기능의 가용성 확인입니다. 이미 제공된 도구는 그대로 쓰고, 호스트에 도구 탐색 기능이 있을 때만 기능 기준으로 찾습니다. MCP 예시의 도구명·인자는 기능과 입력 의도를 나타내며, 실제 호출 이름·서버 별칭·입출력은 연결된 도구 스키마를 확인합니다. 사이트 식별자도 스키마에 맞게 확인합니다. 없는 도구를 호출한 것으로 간주하지 않습니다.
- **스킬 참조**는 호스트의 설치 목록·제공된 위치에서 실제 SKILL.md를 확인합니다. 상대 링크는 링크가 있는 파일 기준입니다. 활성화가 필요한 호스트에서는 해당 절차를 따르고, 별도 호출 도구가 없으면 접근 가능한 본문과 참조를 읽어 같은 세션에서 수행합니다. 설치·발견·접근 실패를 구분하고, 실패하면 해당 단계의 부재 처리를 적용하며 권한을 우회하지 않습니다.
- **프로젝트 지침**은 현재 호스트가 적용한 우선순위와 파일 범위를 따릅니다. 다른 저장소를 조사할 때는 해당 저장소의 관련 프로젝트 지침을 확인합니다.
- 도구·인증이 부족하면 영향을 받는 단계를 명시합니다. 외부 변경은 사용자 지시와 호스트 권한 범위 안에서 [workflow의 확인 절차](workflow.md)를 따릅니다. 일부 변경 후 실패하면 완료·미완료 상태를 보고하고 확인 없이 전체 작업을 반복하거나 자동 롤백하지 않습니다.
